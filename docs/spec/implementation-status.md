## 確定事項

- 事前開発は一人・Windows。大会当日はWindows 1台、Mac 3台、各自のCodexで開発。
- 空のリポジトリから仕様・手順書で再現。4時間実装、1時間調整が目標。
- 内部設計、契約、分担境界を固定する。機能別に分担し、空の機能を先に接続して順次統合。
- 各自のPCで独立開発。統合デモは一台のPCで実行。iPhoneはそのPCへ接続する追加確認。
- 最終的には全7機能。最初の体験は移動に伴う3D地図の成長と文字対話。
- 最初の地域は横浜の新山下・元町・山下公園。OSMの高さが存在する建物のみ3D化し、不明なら平面。
- 解放範囲は軌跡から20m。通過と訪問確認は別。架空再生・実GPSファイル・画面表示中GPSに対応。
- 会話は利用者から開始。場所指定と地図全体に対応。会話中のAIからの質問は可。
- 原文と解釈を自動保存し、毎回保存通知は出さない。本人の言葉と仮説を区別する。
- 自分についての一覧で根拠確認・訂正。個人の好みは保持、最近の行動は既定30日。
- 友人は同じデモPCの利用者間で招待コード→相手が承認。
- 友人との散歩の好みの相性、双方の好みから経路を作成する機能を追加する。
- AIは本人のChatGPTアカウントでCodex経由。API課金への自動切替はしない。枠不足は保存・待機・再試行。
- 外部サービス登録・費用が必要なら具体的な条件を示して都度確認する。

Next.js + React + MapLibre。保存はNode.js 24のSQLiteで、`MapRepository`に閉じ込める。

提案・機能画面には未接続であることを明示し、固定結果を本物のAI処理や歩行経路として返さない。

## 現状の制約

- GPXに精度がない場合はunknownとして保存し、通行済み判定に利用しない。HDOPをメートルへ勝手に変換しない。
- AIには最近の位置記録の件数を渡す段階で、場所別の滞在・訪問候補の自動抽出は未実装。
- 会話は最大20メッセージ、記憶は最大80件をAIコンテキストへ渡す。全期間の検索は今後追加する。
- A/B切替はデモ管理操作。一般公開向けの本人確認ではない。
- デモアカウントA/Bの選択権がある人は両者を操作できる。実際の個人データを入れたまま第三者へ開放しない。
- 自動テストのスマホ幅確認はエミュレーター・iPhone実機での合格を意味しない。

## 歩行視点（2026-09-05追加）

探索表示は位置記録の最新時刻の地点に人型アバターを置き、傾き62度・足元を画面高さ62%に配置する。
位置更新時は中心を追従。探索中は1本指・PCの左ドラッグで人物の足元の周りを円状になぞると、その角度と同じだけ地図が回転する（90度で90度、1周で360度）。±180度の境界を連続して処理し、指を離しても次の操作は現在の向きから開始する。足元18px以内は急反転を防ぐため回転を休止し、外へ出た位置から再開する。回転ボタンは撤去。2本指の回転・ピンチ拡大も中心を固定する。
探索中は地図の平行移動を無効化し、場所選択でも自分から視点を離さない。ホームは従来の地図移動を維持。足元の輪は半径20m。スワイプ後の誤タップを抑止し、複数指操作後は指を全て離してから1本指回転を再開する。
実GPS、架空再生、読込み履歴、未記録時のデモ開始地点をラベルで区別し、表示用の位置を記録には加えない。
地図担当のfeatures/map内に閉じ、他機能・共通API契約への追加依存はない。
iPhoneのLAN HTTP接続では測位できない制約は継続。HTTPS化および実機GPS検証は未実施。
検証：pnpm check（7件成功）、pnpm build、pnpm test:e2e（4件成功）。モバイル幅でマウス回転・時計回り／反時計回りの全周タッチ（90度ごとの一致）・ピンチ前後の足元固定、誤選択防止、ホーム復帰を確認。実iPhoneは未検証。



## タイプ診断（最新合意）

「自分について」はタイプ診断へ変更。探究心・自然志向・文化への関心・食への関心・交流志向・活動意欲の6軸で、本人の会話と最近30日の実測滞在候補からCodexが0〜100を推定する。初期質問・診断結果の手動修正は設けない。根拠不足はnull（推定中）で、0点には変換しない。全軸判定時に多角形、それまでは既知の軸だけ描画する。各軸で理由と原文根拠を開ける。
滞在候補は精度50m以内、連続点の間隔120秒以内、最初の点から30m以内に5分以上。未来・30日以前・架空の点は除外。近隣50m以内の既知の場所に種類を付け、その他は種類不明。訪問目的は不明と明記し、滞在だけの推定は最大60に制限する。
会話は直近80件の本人発言と、直近80件の本人由来の記憶が参照する原文を利用。AIの返答を本人の好みに転用しない。軸の重複・存在しない根拠ID・根拠なしの得点を検証で拒否する。
担当Bがpersonal UIとDiagnosisService、担当Aが滞在抽出を担当可能。共通契約はcontracts/diagnosis.ts、純粋な抽出・検証はdomain/diagnosis.ts、CodexとSQLiteはアダプターに閉じる。診断ページ表示中に有効な入力が変わると更新し、入力ハッシュで利用者別にSQLiteへキャッシュ。接続失敗は再試行を表示。既存の会話・記憶データは保持する。
検証：単体10件成功、E2E6件成功（表示テストのセレクター修正後に対象を再実行）、ビルド成功。Codex実接続で6軸の点数・根拠を取得。390×844の表示確認済み。

## 会話からの徒歩ルート（追加）

会話画面の「この会話から散歩ルートを作る」→出発・到着・必須経由地→AI提案→openrouteservice foot-walking。AIは会話の文脈・本人の記憶から登録済みの候補IDと理由を選ぶ。必須地点の包含・順序、未知ID、重複をサーバーで検証する。住所の捏造や未登録地点への対応はしない。
RoutePlannerAIとWalkingRouterを分離し、RouteServiceで組立て。共通契約はcontracts/routes.ts、経路アダプターはinfrastructure/openrouteservice.ts。結果はSQLiteで本人別保存し、入力が同じなら再利用。会話や位置記録には経路線を混ぜない。キー未設定・接続失敗・上限超過を区別し、道順は実レスポンス取得時だけ表示する。共同経路と友人の共有投影は引き続き未実装。
検証：単体13件・E2E7件・ビルド成功。Codexの実接続で会話に基づく候補選定を確認。ORSはAPIキー未設定のため実通信は未検証。アダプターの座標順序・通過確認・429・失敗時の非代用はテスト応答で確認。

## 建物の演出モデル（最新合意・従来の高さ限定表示を更新）

ユーザーの希望により高さは見栄え優先の補完を許可。観測値のheightは書換えず、render_heightを描画専用に追加する。画面では高さ・外観が演出モデルであると表示する。
住宅・集合住宅・店舗・オフィス・倉庫・公共施設それぞれ10パターン、計60プリセット。OSM building/shop/amenityを優先し、不明な建物は面積で外観用に分類。OSM IDのハッシュでパターンを固定し、再読込み・利用者・端末で外観が変わらない。建物の新規解放時にランダム風の外観が立ち上がる。
建物輪郭に窓・階の縁・屋根・塔屋・店舗ひさし等のポリゴン部品を重ねる。屋根形状と階数・色・セットバックで各プリセットを差別化。屋根以外の高さは4〜38mに制限し、未知はタイプに応じて補完。未探索は平面のまま、20m解放のルールと保存記録は維持する。
features/map/buildingModels.tsに閉じ、他機能への依存追加なし。詳細部品は探索済みだけ生成・キャッシュし、長い壁4面・最大8階・各面5列までに抑える。既存のMapLibreで描画し、外部3Dアセットや追加ライブラリは不要。
検証：単体15件、ビルド成功。E2E既存7件、新規の建物表示確認が成功。探索開始時のカメラ補正後、回転・ピンチと建物表示の2件を再確認。390×844で窓・屋根と人物の足元固定を目視確認。実iPhoneの性能測定は未実施。
