# AIで作る拡張機能（2026-09-08）

## 利用方法

「アプリを育てる」→「自分で機能を作ってみる」で作成画面を開く。
自然文で依頼し、生成された定義・利用情報を確認する。お試し操作は別の保存領域を使う。
操作を一度試してから、利用情報を確認して有効化する。地図の「拡張機能」メニューから使う。
会話で修正版を作れる。公開は機能定義のみ。公開前に定数や初期値に個人情報が含まれないか確認する。
追加した人の保存データは分離され、公開者に戻らない。更新は手動。無効化しても記録は残す。

## 担当と依存

- contracts/extensions.ts：スキーマ・共通型。schemaVersion=1。
- domain/extensions.ts：定義検証、互換性検証、限定命令の実行。外部I/Oなし。
- infrastructure/extension-store.ts：SQLite保存。
- infrastructure/codex.ts：既存ChatGPT認証のCodex App Serverで定義生成。
- infrastructure/extension-geography.ts：固定されたOverpass通信先・検索条件・キャッシュ。
- server/extensions.ts：利用者分離、生成、版管理、試用、公開、権限、実行の組立て。
- features/extensions：共通ダイアログ、フォーム、一覧、作成画面、地図への出力。
- app/page.tsx・features/map/MapCanvas.tsx：マーカーと共通メニューの接続。

任意コード、HTML、CSS、任意URLの評価・挿入はしない。部品の登録先と操作は本体が管理する。
生成AIに渡すのは作成会話と旧定義のみ。場所や会話の実データは実行時に本人の保存領域から読み、定義で宣言された情報だけを処理に渡す。

## DSL v1

場所ごとのレコードに最大16項目（文字列・数値・真偽値）を持つ。既存フィールドの削除・型変更は拒否。
操作は最大8件、各24ステップ。click・visitのイベント、全条件一致のwhen、set/add/multiply/notify/popup。
参照はrecord.FIELD、input.FIELD、placeの属性、event.day/type、許可済みcontextのJSON文字列。
表示部品は入力フォーム・絞り込み一覧・通知/パネル・ピン/成長する木。自由配置はしない。
更新しても既存レコードを保持し、新しい項目は初回実行時に初期化する。

1利用者につき下書き30件、1下書きにつき30版/60メッセージ、追加20件、各機能の保存先300場所。
生成は同一プロセスで同時2件・同一利用者1件。大量ユーザ向けの分散キュー・認証は別途必要。
現在のアプリのA/Bデモ認証を引き継ぐ。インターネット全体への一般公開を実装したものではない。

## 訪問と外部通信

前景の新しい位置更新を受けて到着処理を呼び出す。サーバーも2分以内・精度50m以内・対象地点20m以内を検証。
架空再生を本番の訪問実績にしない。試用では到着を明示的にシミュレーションできる。
訪問処理は場所・操作単位で1日1回（Asia/Tokyo）。アプリを閉じた後のバックグラウンド処理はなし。

地理情報はOverpassの手動検索のみ。カフェ・公園・レストラン・博物館、半径100〜1000m。
外部へ送るのは座標（小数4桁）・施設カテゴリ・検索範囲。会話・メモは送信しない。
承認は利用者・機能ごとに通信先/情報種別/目的を保存。カテゴリ変更は再承認。取消可能。
5秒間隔、1件ずつ、5分キャッシュ、18秒タイムアウト、最大1MB/60施設で取得。
公共Overpassはローカルデモの少数手動検索用。本番で一般ユーザへ提供する際は自前インスタンス等に置換する。
- https://dev.overpass-api.de/overpass-doc/en/preface/commons.html
- https://www.openstreetmap.org/copyright
- https://learn.chatgpt.com/docs/app-server

## APIと検証

GET /api/extensions：本人の下書き・追加済み機能と公開定義。
POST /api/extensions：generate/install/publish/toggle/revoke/run/geography。セッション必須、同一オリジン検証、サイズ・型検証。
runはサーバー保存済みの定義しか実行せず、版番号と有効状態を確認。失敗はトランザクションをロールバック。

pnpm check / pnpm build / pnpm test:e2e。
実AI検証はPowerShellで $env:EXTENSIONS_LIVE='1' とし、pnpm exec vitest run tests/extensions-live.test.ts。
同じ環境変数で pnpm test:e2e は生成・試用・公開・別利用者追加・修正・無効化を実AIで検証する。
実AIテストは通常テストではスキップ。テストDBは本番と分離。

## 保留

任意JavaScript、自由な外部URL、配列や入れ子を持つ保存スキーマ、自動データ移行、独自画像/3Dモデル生成、バックグラウンド通知、大規模公開基盤。

## 検証結果

実Codexによるメモ・成長機能の生成と実行、実AIブラウザでの試用・公開・別利用者追加・修正・無効化を確認。
Overpassへの実接続確認はHTTP 406。通信の成功を確認済みとはしない。承認前の通信抑止、承認保持・取消、送信情報の限定はモック応答で検証。


## ローカルCodexによる開発代行（2026-09-08）

将来、利用者のAIが開発インターフェースに接続する構成を想定し、現在はLocalCodexDeveloperが代行する。
共通仕様の取得→生成→定義検証→架空データでの試行→下書き提出。検証エラーは最大2回AIへ返し修正する。
ExtensionDevelopmentToolsを共通契約、ExtensionDevelopmentKitを本体側の検証実装として分離。
LocalCodexDeveloperはCodexへの接続だけを受け持ち、下書きの保存と有効化・公開権限は本体に残る。
機械的な試行は初期値と架空入力による実行エラー検出であり、すべての条件分岐や利用者の意図を保証するテストではない。
自動検証を通過しても、利用者によるお試しと有効化を省略しない。

現在の接続は同一サーバープロセス内の共通契約経由。利用者のAIへ公開するHTTP/MCP接続・外部AI用認証は未実装。
実際にモデルを動かすのはローカルPCにインストールされたCodexと、そのPCでログインしているChatGPTアカウント。
端末ごと・利用者ごとのAI認証を実装済みと扱わない。保存データの利用者分離は維持する。

## 地図の色分け（2026-09-08）

display.appearanceに基本色colorと条件rulesを指定できる。旧定義で未指定の場合は緑。
色はgreen/blue/coral/amber/purple/tealの6種類。本体の安全な固定パレットへ変換する。
rulesは最大8件。保存項目field、比較op（eq/ne/gt/gte/lt）、比較value、色color、状態名labelを持つ。
先頭から最初に一致したルールを使う。数値の大小比較、文字列/真偽値の一致条件に対応。
未設定の保存項目は定義の初期値で評価。地図マーカーと試用・実行一覧は同じ色決定処理を使う。
凡例と状態名も表示し、色だけで判別させない。AIへの色の変更依頼は通常の修正版として生成・試用・有効化する。
