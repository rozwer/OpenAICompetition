# 実装の開始と進め方

[26件のIssue](../implementation-issues/README.md)を全件未着手で扱い、各Issueと同番号の仕様書を読む。要件の確認責任と分担は[requirements.csv](../requirements.csv)にある。

1. 001で環境・共有型・契約fixture・起動検査コマンドを確定する。
2. 自分の責任範囲と編集パスを確認し、担当・worktreeを記録する。共有契約/トークン/DDLの変更はそれぞれ001/002/003へ集約する。
3. バックエンドは処理と保存、ページはページ内のAI会話を含む全UIを実装する。契約fixtureで独立して進め、提供側の全機能完成を待たない。
4. 所有範囲の反例を検査し、完成した枝から021でAPI・保存・再表示を接続する。外部providerや実機が必要な受入は証拠が得られるまで未完了とする。
5. Issue、PR、worktree、head、差分、コマンド、終了結果、保存・画面証拠、未接続を揃えてレビューし、実際に通った受入だけを完了にする。

原受入を最小実演へ縮めない。機能削除やfakeへの置換で完了にしない。変更・失敗・環境差がない検査は繰り返さない。台帳やhooksの導入は001で実際のコマンドを確認してから案内する。
