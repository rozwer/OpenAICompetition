# 当日の開始と進め方

## 開始前

全員が同じ仕様・契約のコミットから開始する。
最初は[準備P-START](../production-plan/v2/issues/P-START.md)から、OS・runtime・依存の版、検査コマンド、共有契約、UI版、地域入力、外部接続の設定を揃える。
本番の[28単位](../production-plan/v2/ISSUE_INDEX.md)を全件未着手で登録する。旧IDやリハーサルの残件計画を実行台帳へ混ぜない。

## 担当と実装

1. 着手依存が満たされ、編集予定パスが競合しない単位を取得する。担当と専用worktreeを記録する。
2. そのIssueの操作、受入、read_set、必要providerを読む。既知の文書・生成物・証拠パスもまとめて取得する。
3. UI・API・保存・再表示を同じ担当範囲で接続する。共有契約を変える場合は影響する利用側と調整する。
4. 対象の反例と実操作を検査し、commit・PRへ結果をまとめる。共通検査の反復は変更・失敗・環境差があるときに限る。
5. レビュー対象head・差分・検査結果を照合して統合し、当日の台帳へ完了を記録する。通信や終了処理の失敗を完了表示に変えない。

[レビュー前の条件](../production-plan/v2/REVIEW_PREVENTION.md)と[共通受入](../production-plan/v2/common-acceptance.md)を適用する。レビュー依頼にはTask、PR、worktree、head、差分、コマンド、終了結果、証拠、未接続を一組で渡す。

## 運用ツールと未接続

taskctl・mise task・GitHub台帳・hooksはP-STARTで導入し、通常取得・提出・統合・終了と二重取得の拒否を確認する。未導入のコマンドを実行可能として案内しない。

外部providerや実機が必要な受入は接続できるまで未完了とする。独立する操作は進める。機能の削除やfakeへの置換で完了にしない。
