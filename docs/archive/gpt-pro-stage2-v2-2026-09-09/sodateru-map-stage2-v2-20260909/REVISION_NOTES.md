# v1 → v2 の変更

| 対象 | v2の決定 | 狙い |
|---|---|---|
| 工程の時計 | 開始/終了分、合流時刻、担当者ごとの持ち時間を削除 | 推論速度を当てにせず、成果物が揃ったら直ちに次へ |
| 固定担当 | 全件 `assignee=null`。技能は助言のみ | 4人の誰でも、空いたagentでも取得 |
| 依存 | `hard_dependencies` と `connect_after` を分離 | 同じ契約を読むUI/API/計算を並列化 |
| 排他 | feature名でなくファイル/ディレクトリprefixを原子的claim | 無関係な作業を止めず、同じ編集だけ重複防止 |
| 合流 | PRがreadyで依存先がmainに届いた時に統合 | 全員一斉集合・固定統合担当を不要に |
| Issue | 旧56件→106件。関数/UI/API/結合へ分離 | 巨大担当Issueの完了待ちをなくす |
| 共有データ | JSON snapshot→SQLite、DDL・列・FK・indexを提供 | 訂正、共有、AI遅着が同じ正本を扱える |
| API | 抽象command一覧→HTTP・DTO・status・null・競合を固定 | request/responseの独自解釈をなくす |
| 高度機能 | 本体改造・新コード・デプロイを後続タスクに維持 | 他の基盤全完成を不必要に前提にしない |

元の145要件と追加12要件を削除していない。`LEGACY_ISSUE_MAPPING.csv`で旧56件を全件追跡する。要件表の `user_value` と `original_acceptance_preserved` は旧版の原文を保持する。参考画像、現在地報告、研究への位置付けは変更せず、実装構成に関する記述だけ本版を優先する。

「無依存」は共有契約すら不要という意味ではない。本パッケージに含まれるv2契約を既に配布された前提として扱う。新たに不明点が出た場合は契約変更を小さく独立させ、完成待ちの間に他のREADY作業を取る。
