# Codexのタスク取得指示

SPEC_INDEX.md、TASK_EXECUTION.mdを読み、取得したIssueと関連DTO/Portだけを追加で読む。時間枠やA/B/C/Dの固定所有はない。

編集前にtools/taskctl.pyでREADYの1タスクをclaimし、返却base_commitから専用worktreeを作る。書込みは取得済みpath内だけ。別pathが必要なら先に全取得し、競合した場合は書かない。失敗したclaimを成功扱いせず、mainをforce-pushしない。

contracts/domain.tsとcontracts/ports.tsを使う。connect_afterが未実装なら明示fakeでmoduleを完成させ、別taskを勝手に再実装しない。fixtureの成功をlive接続と報告せず、AIの固定結果/別providerへの無断切替をしない。

受入証拠と未接続箇所を付けてsubmitする。通常merge/fast-forwardでcommit到達性を保ち、main到達後にlandする。停止時はbranch/引継ぎnoteを残してreleaseし、別のREADY/POOLへ移る。経過時間だけで他人のlockを奪わない。

APIとDBはOpenAPI/schema.sqlを正本とし、変更はCONTRACT_CHANGE.mdに従う。原文と本人stateを保持する。任意生成codeを現行app内でevalしない。
