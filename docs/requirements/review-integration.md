# レビューの反映方針と次の議論

更新日：2026年9月8日

ダウンロードされたGPT ProのStage1完成案を、ユーザーの「良い案だと思います。反映して議論をしましょう」という依頼に基づき採用方針として反映した。[要件と受入条件](reviewed-requirements.md)を今後の基準とし、以下の具体化を続ける。元出力の「新提案は個別承認済みではない」は出力時点の記述として原本に残す。

## 製品の中心

場所で何をし、何を得て、なぜ選んだかという理解を育て、自分の街、他者との比較、別の街での行動へ使える地図にする。日常の入口は帰り道の短い寄り道や、一つの場所についての一言。旅行・防災・バイク・聖地などの既存の用途も保持する。

一言の記録から用途と理由を残し、建物が変わる。理由を振り返り、本人が解釈を訂正すると、次の提案が変わる。他者の体験を別の街で試し、自分の感想を持ち帰る。この流れを4タブ共通の体験IDと根拠の参照でつなぐ。

## 具体化を続ける点

| 論点 | 現段階の置き方 | 次に決めること |
|---|---|---|
| 行動プロファイル | 条件付きで根拠と反例を示す方向を採用。二者選択モデルは候補 | 属性、質問、更新単位、本人へ見せる発見の形、評価方法 |
| 体験レシピ | 順序と理由を持つ構造を採用 | 最初の実演で使う一つの体験と、編集できる粒度 |
| OpenUAS | 地域候補取得へ組み込む。名古屋/東京は推奨候補 | 実際の収録・版・利用条件、検索範囲、あり/なしの比較方法 |
| 成長 | 用途で本体が変わり、再訪で装飾が育つ | 多用途の合成、造形、段階境界。1/3/7/15/30回は案であり確定値ではない |
| 技術選定 | 既存のMapbox、Node.js/Bun、MacのPostgreSQL/PostGIS等を引継ぐ | UIフレームワーク、交通API、プラグイン隔離、描画方式の成立性 |
| 実演・工程 | 一言→形→訂正→別都市→拡張→感想を中心とする | チーム人数・担当・公式の発表時間・外部条件と当日工程 |

詳細な設計値の出所はGit保存コミットの `docs/archive/gpt-pro-stage1-2026-09-08/STAGE1_HANDOFF.md` 第12・13節にある。外部API・大会条件・研究データの記載は提供されたレビューの調査結果であり、今回の反映作業では再検証していない。

## 最初に議論したい体験

「ここで本を読んだ」と記録して建物が変わる楽しさから入り、そのあと「なぜここだったか」の理解と訂正へ進む構成を推奨する。初回から診断を完成させる前提は置かず、一言だけでも利用価値を返す。

たとえば「静かだから選んだ」という解釈を「今日は時間がなかっただけ」と直す。次の提案では近さや時間の扱いが変わり、過去の訪問と読書の記憶は残る。順位が変わるケースを実演しつつ、変更の影響がない場合に無理な順位変動を作らない。

次に、他の街でも試したくなる体験を一つ決める。「本屋で新しい話題に触れる→空が見える場所で一息つく」を仮の主シナリオとし、残したい理由と変えてよい場所を具体的に話す。研究名や内部の推定方式は、この体験が動くための選択として後から決める。

## 反映範囲と資料の扱い

原本8ファイルはGit履歴に保存している。受領時にZIP内ハッシュと単独ダウンロード2文書の一致を確認した。137要件のID・本文・受入条件、旧55件の対応を収録した。SELF-009には、訂正のたびに順位変動を強制しない補足を加えた。

タブ別要件の説明、文書の入口、既存仕様の参照先、デモを更新した。既存APIや詳細な型定義には新しいプロファイル・レシピ・候補取得・評価の未反映部分があるため、第2段階で整合させる。試作コードの機能追加や実行試験を行った扱いにはしない。

## 推薦と認知的対立の具体化案

ユーザーの追加依頼に基づき、過去のローカル推薦資料と一次研究から[理由の発見と推薦をつなぐ提案](../research/recommendation-cognitive-conflict-2026-09-08.md)を作成した。確認済み理由による推薦、根拠付きの意外な候補、任意の比較・訂正の一問を組み合わせる設計案。137要件の確定変更ではなく、SELF・TRF・ROUTE・EVALの具体化として議論する。

ユーザーが参照を求めた独立したセレンディピティ実験プロジェクトを確認し、[街の対象から新しい関心へつなぐ案](../research/serendipity-project-reuse-2026-09-08.md)を追加した。先のmarumado参照を主対象とした説明を訂正する。理由を保つ推薦に加え、体験を通して新しい関心が生まれることを扱う提案として議論する。

## セレンディピティの要件取込（2026-09-08）

ユーザーの「改めて取り入れ、質問をして」の依頼に基づき、DISC-001〜008を追加した。全145件となり、元137件と旧55件の対応は維持する。街の対象→意外な知識→新しい関心→次の探索を共通の体験へ接続する。元の実験条件や生成モデル・数値の自動採用はしない。

回答により次の3点を確定した。

- 提示タイミング：自分で開く＋余裕があるときだけ提案。
- 中心となる価値：その場で見方が変わり、もっと知りたくなること。次の目的地への推薦は任意の後続導線。
- 探索範囲：本人が探索を選んだ場面では苦手な分野も含める。通常提案に許可を持ち越さず、表示禁止・停止は別に尊重する。

残る設計事項は、余裕の判定方法と提案頻度、探索を始める操作、最初の発見カードの内容・長さ・続きを知る導線。時間が空いていることだけで受取り希望を推測しない。

旧版の参照資料はGitの保存コミット `5abdf93` にある。過去の検証経緯を調べる場合のみ `git show 5abdf93:<当時のリポジトリ相対パス>` で確認する。実装判断には現行要件を使う。
