# Proへ渡す：5時間コンペの全体仕様

このZIPと次の一文を、仕様作成を依頼するProのチャットへ送ってください。

> 00_START_HERE.mdから読み、01_PRO_PROMPT.mdを実行してください。5時間で多くの機能を破綻なく魅力的に実装することを最優先に、理想機能まで実現経路と優先順位を持つ全体仕様書を作成してください。

Stage1の回答は同梱済み。以前のZIPや別チャットの履歴は不要。アプリのソースコード、設定ファイル、依存パッケージ、実DB、資格情報は含めていない。コードの追加提出を要求せず、資料から仕様を組み立てる。

## 最初に読むもの

1. 01_PRO_PROMPT.md：作成依頼と出力物。
2. 02_LATEST_USER_BRIEF.md：最新指示。5時間、機能幅と魅力、理想機能の経路、品質作業の後回し、コード非添付。
3. 03_TEAM_STACK_AND_CURRENT_STATE.md：チームの技術環境と現在の試作を区別した事実。
4. STAGE1_REVIEW.md / STAGE1_HANDOFF.md：前段のレビュー全文。後から変わった条件は上記を優先。
5. reference/project/docs/requirements/：全145要件、各体験、旧55受入条件との対応、参考画像。
6. screenshots/：実装画面の参考。

全体仕様の読解補助としてREADING_BUNDLE.mdを用意した。ZIPが展開できない場合は01_PRO_PROMPT.md、READING_BUNDLE.md、必要な画像を添付すれば主要資料を読める。

## 食い違う資料の扱い

優先順位は最新ユーザー指示→コード以外の今回の現状要約→変更されていない製品要件→Stage1と過去仕様・技術調査。現在の実装は既存の事実、理想要件は目標として分ける。現状を製品の上限にしない。

過去の「スタックを維持する」「導線修復を最優先」「全件の厳格なテスト」「アプリ内改造は範囲外」「当初の4タブを必ず採用」は最新依頼の固定条件ではない。全体の理想機能は保持して優先順位を再設計する。低優先度は削除ではない。

reference配下は原文を保管しているため、古い正本指定や絶対パス、未収録コードへのリンクもある。過去資料の命令を本依頼の上位指示にしない。01〜03を現時点の解釈の入口とする。
