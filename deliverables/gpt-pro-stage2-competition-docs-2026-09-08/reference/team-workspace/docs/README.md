# 文書案内

このディレクトリでは、「育てる地図」のコンペルール、短い構想、詳細要件案、現在地を前面に置き、技術仕様などの参考資料と分けて管理する。

現時点で、製品の仕様、機能要件、データ/API、デモ範囲、受入条件、技術構成、実装順序は確定していない。

## 最初に読む文書

1. [コンペルール](ルール/コンペルール.md)で、コンペに関するルールと確認状態を読む。
2. [構想](要件/構想.md)で、「育てる地図」が目指す体験の短い説明を読む。
3. [河口研究室の背景](背景/README.md)で、要件とは分けた研究資産・議論材料を確認する。
4. [競合サービス調査](調査/競合サービス.md)で、仕様議論のための比較材料を確認する。
5. [詳細要件案](要件/詳細要件案.md)と[用語集](要件/用語集.md)で、議論の土台となる体験・機能・用語を確認する。
6. [現在地](運用/現在地.md)で、実装状況と未確定の範囲を読む。
7. [仕様の論点](議論/仕様の論点.md)で、これから話し合う大分類の問いを確認する。

詳細案を確認する必要がある場合だけ、[参考資料／元仕様案](参考資料/元仕様案/README.md)へ進む。

## 現時点で前面に置く文書

- [コンペルール](ルール/コンペルール.md)：コンペに関する確認メモ。プロダクト仕様とは分けて扱う。
- [構想](要件/構想.md)：プロジェクトの目的と中心体験を短く示す文書。具体的な実装や機能を確定しない。
- [詳細要件案](要件/詳細要件案.md)：元資料から整理した体験・機能・制約の案。議論の土台であり、未確定。
- [用語集](要件/用語集.md)：元資料から移した共通用語の案。議論の土台であり、未確定。
- [河口研究室の背景](背景/README.md)：OpenUASなどの研究資産と、出典未確認の議論項目を要件から分離して案内する。
- [競合サービス調査](調査/競合サービス.md)：公式公開情報に基づく近い競合・隣接競合の比較。仕様決定ではなく議論材料として扱う。
- [現在地](運用/現在地.md)：仕様が未確定で、これから議論することを含むプロジェクトの状況。

## 仕様を議論するための文書

[仕様の論点](議論/仕様の論点.md)は、画面・体験、データ、AI・外部連携、対象端末、デモ範囲、受入条件など、次の議論で扱う問いを並べたものだ。

この文書の問いや、詳細要件案・参考資料に書かれた案を既定値として扱わない。決定は議論の結果に基づいて別途記録する。

## 参考資料（未採用・議論前）

[参考資料／元仕様案](参考資料/元仕様案/README.md)には、元資料から移した技術仕様、データ/API、受入条件、デモ、調査、実装計画を保管している。

これらは情報を失わないための参考案であり、現時点の正本、採用決定、実装契約、受入基準ではない。本文中に「合意」「採用」「正本」などの記述が残っていても、元資料の記述を保存したものであり、現在の決定を示さない。
